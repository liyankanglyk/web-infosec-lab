# Web信息安全性实验系统 部署与运行指南

**版本：** V1.2（对应实际实现；**环境中立**，适用于任意 Apache + PHP + MySQL 部署）

---

## 1. 环境要求

| 组件 | 要求 |
|------|------|
| 操作系统 | Windows / Linux / macOS（本文命令以 Windows 为主） |
| Web 服务器 | Apache 2.4+ |
| PHP | 7.3+（需 `pdo_mysql`、`mysqli`；不使用 7.4+ 专属语法） |
| 数据库 | MySQL 5.7 / 8.0（需 `utf8mb4`） |
| 浏览器 | Chrome、Firefox、Edge 等主流浏览器 |

Apache / PHP / MySQL 可以是一键集成环境，也可以是独立安装，**本系统不依赖任何特定环境发行版**。phpMyAdmin 为可选工具（导入建库脚本同样可用命令行）。

## 2. 快速部署（Windows）

### 2.1 放置项目

将项目目录整体复制到 Apache 的站点根目录（各环境常见名为 `htdocs\`、`www\` 或 `html\`）：

```
<Apache 站点根目录>\web-infosec-lab\
```

目录名必须保持 ASCII（`web-infosec-lab`）。仓库内含文件清单见 [README.md 的目录结构](../README.md)，代码层职责划分见 [AGENTS.md](../AGENTS.md)，本文不重复列。

### 2.2 初始化数据库（两种形态二选一）

> 术语约定：本文使用**单租户 / 多租户**；《测试需求.md》§1.2 的"单机构部署形态"即本文的单租户形态，机构在界面与代码中写作"组织 / org"。

#### 模式 A：单租户（默认，最简单）

通过 phpMyAdmin（`http://localhost/phpmyadmin`）或命令行导入 `sql/业务库建库脚本.sql`：

```bash
mysql -u root < sql/业务库建库脚本.sql
```

该脚本会自动创建 `websec_db` 数据库、全部业务表、4 个角色与默认账户 `superadmin`。

> 脚本文件名为中文（仅由 PHP/命令行从磁盘读取，不进 URL）；`index.php` 的 `businessSchemaFile()` 同时兼容早期 ASCII 文件名，但**库名与本版本不同时不能直接复用旧库**，请重新导入。

#### 模式 B：多租户平台模式

1. 导入 `sql/平台库建库脚本.sql` 创建平台库 `websec_platform`（组织表、平台管理员表、平台审计表）
2. 系统启动时自动检测平台库（`config_database.php` 中 `platform` 配置），检测成功即进入多租户模式
3. 首次访问 `http://localhost/web-infosec-lab/platform/login` 设置平台管理员密码
4. 在平台中创建组织，系统自动创建该组织独立数据库并初始化（详见第 4 节）

> 注意：多租户模式下业务系统通过 `/{org_code}/` 前缀访问；未导入平台库时自动回退单租户模式，两种部署互不影响。

### 2.3 配置数据库连接

先复制模板再生成本地配置（`config_database.php` 含真实凭据，已被 `.gitignore` 排除，不要提交）：

```bash
cp config_database.example.php config_database.php
```

然后编辑 `config_database.php`：

```php
$config = [
// 平台管理库（多租户模式）
'platform' => [
'host' => 'localhost', 'port' => 3306,
'database' => 'websec_platform',
'user' => 'root', 'password' => '你的 MySQL 口令',
'charset' => 'utf8mb4'
],
// 默认业务库（单租户兼容模式）
'database' => [
'host' => 'localhost', 'port' => 3306,
'database' => 'websec_db',
'user' => 'root', 'password' => '你的 MySQL 口令',
'charset' => 'utf8mb4'
],
];
```

> MySQL 默认端口为 3306；若你的环境改过端口，两个块的 `port` 需同步修改。口令填错会直接报 `Access denied for user ... (using password: YES)`。

### 2.4 启动与停止

本仓库不附启停脚本（Windows 专用批处理与本机路径绑定，不利于跳环境复用）。按你本机的方式启动与停止服务即可：

| 操作 | 方法 |
|------|------|
| 启动 | 启动 Apache（加载 PHP 模块，`DocumentRoot` 指向站点根目录或配 vhost 指向本项目）与 MySQL；可用系统服务、`apachectl start` / `net start <服务名>` 或任一集成环境的服务面板 |
| 停止 | 同上反向操作；若仅想停掉测试实例，先停 Apache 再停 MySQL |
| 验证 | 查看监听端口是否已建立（Apache 默认 80、MySQL 默认 3306）：Windows 下 `netstat -ano` 后看对应端口，Linux 下可用 `ss -lntp` |

### 2.5 登录与默认账户

访问 `http://localhost/web-infosec-lab/`，系统按部署模式自动判定入口：

| 场景 | 登录入口 | 用户名 | 密码 |
|------|---------|--------|------|
| 单租户业务系统 | `/login` | `superadmin` | `123456` |
| 平台管理（多租户） | `/platform/login` | `admin` | 首次访问时自行设置（无默认密码） |
| 组织业务系统（多租户） | `/{org_code}/login` | `superadmin` | `123456` |

> `superadmin`/`123456` 是刻意预埋的默认账户（DEF001/DEF002），属于本样例的检测靶点，请勿“顺手修复”。

#### 忘记密码怎么办

- 平台管理员（admin）：密码以 bcrypt 存储，无明文可查。重置方法：在 phpMyAdmin 中执行

  ```sql
UPDATE websec_platform.platform_users SET password_hash = '__FIRST_RUN__' WHERE username = 'admin';
  ```

重新访问 `/platform/login` 即会再次弹出“首次初始化”界面，重新设置密码。

- 组织/单租户业务系统用户：密码为**明文存储**（DEF005 预埋缺陷），直接查库即可看到：

  ```sql
USE websec_db;                          -- 组织模式下换成对应组织库 websec_org_{code}
SELECT username, password_hash FROM users;   -- password_hash 即明文密码
  ```

也可直接改密：

  ```sql
UPDATE users SET password_hash = '新密码' WHERE username = 'superadmin';
  ```

### 2.6 系统初始化（可选）

以 `superadmin` 登录后打开“系统设置”页（`/help/settings`），点击“初始化系统”：

- 重建全部业务表并重新执行 `sql/业务库建库脚本.sql`（唯一数据源）
- 生成约 4990 条演示审计日志（便于审计类缺陷测试）

## 4. 多租户平台部署

### 4.1 平台首次登录

1. 访问 `/platform/login`
2. 首次访问时系统检测到平台管理员密码为 `__FIRST_RUN__` 标记，引导设置初始密码（`password_hash` 使用 PHP `password_hash` 存储）
3. 设置完成后以平台管理员登录

忘记平台管理员口令时：将 `websec_platform.platform_users` 中 `admin` 的 `password_hash` 改回 `__FIRST_RUN__`，再次访问登录页即可重新设置（详见 §2.5）。

### 4.2 创建组织

在平台“组织管理”中点击创建，填写：

- **组织代号**（org_code）：用于 URL 路径与库名，如 `hubei001`
- **组织名称**
- 数据库参数：系统自动生成独立数据库名 `websec_org_{code}`、MySQL 用户名与随机密码

创建完成后系统自动执行：

1. 创建独立数据库与 MySQL 用户
2. 导入 `sql/业务库建库脚本.sql` 初始化全部业务表与种子数据
3. 生成演示审计日志

### 4.3 组织维护

| 操作 | 说明 |
|------|------|
| 查看 | 查看组织详情（数据库连接参数、初始化状态） |
| 编辑 | 修改组织名称、备注等 |
| 停用/启用 | 停用后组织代码不再路由（`status='inactive'`） |
| 初始化 | 重新初始化组织数据库（清空重建） |
| 删除 | 删除组织记录并删除其独立数据库 |

### 4.4 组织访问

用户访问 `http://localhost/web-infosec-lab/{org_code}/dashboard`，系统自动切换到该组织独立数据库；切换组织时清除旧登录状态。

## 5. 备份与恢复

### 5.1 系统内操作

- 手动备份：登录后进入“备份管理”→ 点击创建备份，SQL 备份文件生成于 `backups/` 目录并写入 `backup_records` 表
- 恢复：在备份管理中选中备份记录并提交恢复（会重建数据库数据）
- 下载：可将备份文件下载到本地保存
- 自动备份开关：仅会话级开关（DEF012 预埋缺陷，无实际定时任务）

### 5.2 命令行备份

```bash
# 备份业务库
mysqldump -u root websec_db > backup_$(date +%Y%m%d).sql

# 恢复
mysql -u root websec_db < backup.sql
```

## 6. 常见问题排查

### 问题 1：无法连接数据库

1. 确认 MySQL 已启动（用你环境的服务面板，或 `netstat -ano | findstr :3306`）
2. 检查 `config_database.php` 主机/端口/账号密码
3. 确认数据库已导入：
   ```sql
SHOW DATABASES;      -- 应包含 websec_db（及 websec_platform）
USE websec_db; SHOW TABLES;
   ```

### 问题 2：页面报错 / 表不存在

- 多租户模式下业务数据必须通过 `/{org_code}/` 前缀访问（此时连接的是组织库）
- 直接访问 `/dashboard` 时连接的是平台库（无业务表），属正常现象；如需单租户模式，不要导入 `sql/平台库建库脚本.sql`（或删除 `websec_platform` 库）

### 问题 3：Apache 无法启动

- 检查 80 端口是否被占用：`netstat -ano | findstr :80`
- 以管理员身份运行 Apache，或改用其他监听端口（记得同步修改启停脚本里的 `APP_URL`）

### 问题 4：看到 PHP 源码而不是网页

- 确认 Apache 已加载 PHP 模块（`httpd.conf` 中的 `php7module` / `mod_php` 与 `DirectoryIndex index.php`），重启 Apache 后重试

### 问题 5：系统运行异常

- 错误日志：`logs/YYYY-MM-DD.log`
- Apache 错误日志：`<Apache 安装目录>\logs\error.log`

## 7. 运行时产物

本文只说运行后**会产生什么**（仓库文件清单见 README）：

| 产物 | 说明 |
|------|------|
| `logs/YYYY-MM-DD.log` | `logError()` 写入的应用错误日志（按日期） |
| `backups/backup_YYYYMMDDHHMMSS.sql` | 备份管理页导出的明文 SQL，含用户表（含明文口令），不得外发 |
| `restore_records` / `backup_records` 表记录 | 备份与恢复的库内留痕（注意：存在 DEF021、DEF025 等审计缺陷） |
| `sess_*` 会话文件 | PHP `session.save_path` 指向的目录，属本地垃圾文件，不入库 |

上述三项产物均已在 `.gitignore` 中排除（目录以 `.gitkeep` 保留）；`config_database.php` 因含真实凭据同样不入库，只发布 `config_database.example.php`。
